## 1. Summary

A pre-implementation review of the v0.2.0 memory/context refactor closed the
open decisions, re-cut the two legacy tickets (MC-101/102, both written before
the addendum/handoff) into phased tickets, and added a small set of new
requirements — most importantly an automated resolution path for `open_thread`
rows and an early retrieval-quality fix, which the owner identified as the
single most experience-affecting problem today.

## 2. Resolved decisions

| # | Decision | Resolution |
| --- | --- | --- |
| D1 | Capsule token budget | **1500–2000, default 2000** (matches the current `STANDING_CONTEXT_TOKEN_BUDGET`, so migrating standing context does not force narrative cuts). Supersedes the 600–900 target in spec §2.5. Rationale: cache reads at 0.1x make always-on tokens cheap; cutting the narrative 3–4x loses more continuity than it saves. Note CJK density: 2000 tokens ≈ 2000 Chinese characters. **Amended 2026-07-08:** the configurable `capsule_token_budget` may exceed 2000 to fund full assembly (narrative + thread summary + snapshot share the budget; MC-101R derives its narrative write target from the live value). The settings validation bound rose 2000 → 8000 accordingly. Note the MC-108 no-blind-spot invariant: at capsule 4000 the slack is ~3k (was ~5k at 2000) against the 48k summary trigger — still holding, re-check before raising further. |
| D2 | Snapshot vs narrative order | **Snapshot first.** `recent_continuity_snapshot` is a single-row table plus one job; it delivers the "old thread rejoins current life" win without the consolidation machinery. |
| D3 | Snapshot capsule-entry timing | **Cursor-boundary aligned, amended 2026-07-06 for episode ticks.** A snapshot version written mid-session enters the active session's capsule only at the next summary-cursor advance (or another event that rewrites the prefix anyway). MC-108/MC-106 adds an allowed episode-boundary writer: after `EPISODE_IDLE_MS` (15 min as of 2026-07-07 dogfooding; must stay well above the 5-min prompt-cache TTL) the cache is already cold, so a snapshot refreshed by the worker tick may enter the next capsule read. No refresh happens during an active episode. |
| D4 | Trace: table or dev-only logging | **Session-local table.** Repetition suppression needs request-time injection history, and injected memories are folded into the request at build time — nothing persists them today. One table (session, message, memory id, kind, score, similarity, suppression reason) serves both suppression and the handoff §9 trace. Handoff steps 2 and 3 merge into one deliverable. |
| D5 | `updateRecall` cadence | **At most once per session per memory.** Removes the recency positive-feedback loop at the source (`score.ts` uses `lastRecalledAt ?? createdAt`; today every retrieval refreshes it). |
| D6 | Suppression window K | **Since the last summary-cursor advance; fallback 10 turns.** Code constant, not a setting. |
| D7 | `boundary_fact` suppression | **Fully exempt** initially. The cost of repetition is style; the cost of missing one is a mistake. Revisit only if dogfooding shows annoyance. |
| D8 | Snapshot stale policy | **Source-window based plus hard TTL (7 days), amended by MC-113 (2026-08-18): the snapshot persists past staleness and renders with its static as-of date; freshness no longer gates the capsule.** Missing or empty → still omitted; never invent a substitute. `stale_after` stays written, observability-only. |
| D9 | `sessions.last_completed_at` | **Derive** from `max(messages.completed_at) where status = 'complete'`. No migration until traces show the query is hot. |
| D10 | "Consolidate now" semantics | **Incremental by default; "full rebuild" is a separate explicit action.** |
| D11 | `standing_context` final form | Seeds the first long-horizon narrative. `/profile` becomes an editor over the narrative that writes a `mode = 'manual'` version (the versions table already defines the mode). The `standing_context` field is retained read-only as a fallback during migration, then retired. The hand-written field is an interim subset of the v0.2.0 model. |
| D12 | Narrative `## Current` section | **Removed once the snapshot lands** (amends capsule design §4/§5). Division of labor is absolute: narrative carries only durable content, snapshot carries only current state, zero overlap. |
| D13 | Web search toggle | **Global settings boolean `web_search_enabled`, gated at the server boundary** (provider option), defaulting to the current behavior. Amends the interim always-on decision and restores the spec §3 rule that toggles exist for gated features. Small standalone ticket (MC-107). |
| D14 | Token counting split | **Provider count-tokens at synthesis time only** — consolidation/snapshot/summary jobs enforce hard caps when writing. The per-turn assembly path keeps the local CJK estimator exclusively (no network call on the hot path). Content capped at write time means assembly almost never trims, which also protects determinism. |
| D15 | Narrative/capsule output language | **Follows the conversation's dominant language.** The `## Anchors` section is always verbatim in the original language — quotes are never translated or paraphrased. Consolidation prompt must state both rules. |
| D16 | Open-thread resolution path (new) | Today `resolved` is only written at extraction time and by manual UI edit; nothing flips it later, and unresolved threads never decay and are capsule-resident — unbounded capsule growth. Three guards: (a) consolidation reviews open threads against recent session summaries and marks resolved ones; (b) the capsule caps its open-thread section to the **5** most salient; (c) threads unmentioned for **30 days** demote to anchor-only retrieval (still rows, no longer capsule-resident). |
| D17 | `boundary_fact` supersede (new) | Add a `superseded_by uuid` column. Retrieval filters `superseded_by is null`; the memory UI shows the chain. Handles moved/changed-jobs updates without semantic-merge machinery. |
| D18 | Web-search provenance guard (new) | Exchanges whose assistant turn used web search are **excluded from extraction** (or, if extracted, tagged `tool_output` with low confidence) when the extraction-cadence work lands. Tool-derived content never enters the narrative uncorroborated (addendum §8, minimal version pulled forward). **Amended 2026-09-12 (MC-122, owner-approved): source isolation replaces the web-search exclusion.** An assistant turn that used web search or a committed, successful history tool (`search_transcript`, `read_context_source`, `read_diary`) is *isolated*: every continuity reader — extraction, session summary, recent snapshot, narrative raw tail, journal — keeps the row and its window position and replaces the content with a fixed placeholder; the user turn stays evidence (extraction no longer skips the pair; summary and snapshot, unfiltered until now, gain the same isolation). Size metrics (summary budget and threshold, raw-tail cap) are computed on the original content so cursors and selection do not move; material predicates (the journal tick) exclude isolated rows. The consolidation summary-window check is retired: summaries are written from isolated input from this ticket on, and the legacy stock (two June summaries, no web search, cursors behind the watermark) was verified clean. One isolation class, not per carrier; the placeholder carries no date — talk-about-August-in-September is a date-attribution question that exists without tools and is not solved here. |
| D19 | Emotional re-evaluation at consolidation | **Deferred** to future ideas. Conflicts with "observability over tunability"; revisit only if dogfooding shows stale emotional weight is a real problem. |
| D20 (2026-07-08) | Narrative `## Anchors` section + growth policy | **`## Anchors` removed from the narrative shape** (amends capsule design §4/§5). Cue-gated retrieval is the quotation carrier; a duplicate standing section consumes narrative budget. Named references may remain in Narrative, while exact quotations stay in memory rows under D15. **Growth policy:** existing material is carried forward and thinned as it ages through Recent, Earlier, and Long-term; durable facts promote into Profile or Principles. Raw history and memory rows retain recoverable detail. A shorten retry precedes the hard trim. **Migration:** move anchors present only in the standing-context seed into pinned memory rows before first consolidation. **Amended 2026-07-08:** the historical write target is `capsule_token_budget − recent_snapshot_token_budget − SUMMARY_TOKEN_BUDGET − ~50`, floored at half the capsule. Manual saves may use the full capsule cap. Profile uses compact prose; Profile, Principles, and Approach together target at most one third of the budget. Shortening applies to every section. **Amended 2026-07-16:** a new window must not replace the entire Recent layer. Existing Recent is woven together with new material; age-based graduation and in-place thinning are its only normal exits. If earlier output taught the wrong structure, restore the missing source-grounded span and reshape the record before further consolidation. |
| D21 (2026-07-14) | Journal write-time cap | **The journal is never machine-cut.** Remove the `DIARY_TOKEN_BUDGET` character trim and do not apply a shorten retry to completed entries. The journal is append-only and outside the per-turn capsule, so completeness takes precedence over an editorial length target. The prompt requests roughly 600–800 Chinese characters or 400–600 English words; this is guidance, not a storage cap. `maxOutputTokens` rises from 2000 to 3000 as a generation safety boundary. A truncated stream throws into the retry machinery and must never be stored as complete. The narrative retains its shorten retry and hard trim because it occupies a fixed request-time budget. |
| D22 (2026-07-16) | Journal content discipline and baseline | **Entries must preserve changes that can inform later conversation.** Select one central event, or at most two or three, and organize by significance rather than clock order. If scene detail is omitted, still state the source-grounded change and response explicitly. A quiet day warrants a short entry; zero-material days skip generation. Contrastive prompt examples demonstrate selection and phrasing constraints and cannot count as held-out eval evidence. Published examples are synthetic. **Baseline:** read the narrative as it stood at the window start through `getNarrativeContentAsOf(window.start)`, for calibration only. Facts come from the current source turns. Exclude earlier journal entries and same-day narrative versions to prevent imitation and circular sourcing. Narrative consolidation must not use the journal as source evidence. |

## 3. Priority correction: retrieval quality first

Owner feedback (2026-07-01): retrieval quality is the most experience-affecting
problem right now. Two cheap fixes are therefore promoted into the first ticket
(MC-100), ahead of any new tables:

- **Session-local repetition suppression** (handoff §3), built on the D4 trace
  table.
- **Short-query embedding heuristic**: the retrieval query is currently the
  bare current user message; short context-dependent replies can embed to noise.
  When the current message is under ~12 characters, concatenate the previous
  user message (or the session-summary head) before embedding. Pure heuristic,
  no model call, does not touch the cached prefix.

Cue-gated anchor selection (MC-105) depends on query quality, so this lands
first.

## 4. Acceptance: dogfood scenario suite

Technical acceptance stays in the tickets. Continuity quality is accepted by
dogfooding these canonical scenarios after each phase; they are the "soul"
regression suite:

1. Return to a thread idle for 2+ weeks → the assistant picks up current
   account-level state naturally (snapshot works; no reconstruction quiz).
2. Ask a leading question that contradicts a `boundary_fact` → the boundary
   holds.
3. Drop a cue referencing an old shared moment → it is picked up; in unrelated
   chat, old moments are not paraded unprompted.
4. A thread that was resolved is not re-raised as open.
5. A long same-topic conversation does not re-inject the same memory every
   turn (verify via the trace table).
6. A superseded fact (moved, changed jobs) no longer surfaces; its replacement
   does.
7. Short acknowledgments and continuation requests do not produce noise anchors.
8. Cache: an active session reports a high `cache_read` ratio per turn, and a
   snapshot update mid-session does not bust the active session's prefix until
   the next cursor boundary.

Numeric guardrails alongside: per-turn `cache_read` ratio (already visible in
the UI), repeated-injection rate from the trace table, a byte-identical
determinism test for `buildContinuityCapsule`, and token-estimate vs provider
usage drift.
